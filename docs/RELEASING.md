# Releasing Deadline Watch

**Feature development:** feature branch → commit → pull request → tests → review → squash merge to main.

**Bug fixes:** user issue → fix branch → commit → linked PR → merge. Keep public issue status meaningful.

After merging into main, GitHub Actions automatically runs tests, builds a four-file installable ZIP, and publishes it to the manifest-matched GitHub Release. PRs never publish.

For a new manifest version, the workflow creates a new versioned release. For intentional same-version fixes on a mutable release, it compares the ZIP, skips identical files, and replaces changed assets automatically. The version tag is not moved; GitHub autogenerated source archives still refer to the original tag commit. Release notes record the latest build commit.

Do not install the source archives. Install the ZIP under Assets. If immutable releases are enabled, a new version is required.

Never commit personal task data, authentication credentials, or backup exports.
